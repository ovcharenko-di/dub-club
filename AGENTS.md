# AGENTS.md

Инструкции для ИИ-агентов (и людей), которые работают с этим репозиторием.

## О проекте

**Dub Club** — браузерная голосовая пати-игра в духе «The Choicer Voicer». Игрок слушает реплику, повторяет её в микрофон, а три «судьи» оценивают сходство с оригиналом. Кроме игры в приложении есть режим дубляжа видео, редактор реплик с субтитрами и паки реплик.

- Чистый статический сайт: HTML, CSS и нативные ES-модули. **Нет сборки, нет npm-зависимостей, нет сервера.** Так и должно остаться: не добавляй бандлеры, фреймворки и `package.json` без явной просьбы.
- Все данные пользователя хранятся только в браузере (IndexedDB). Наружу ничего не отправляется.
- Интерфейс, тексты судей, сообщения об ошибках и README на **русском**. Имена в коде, комментарии и сообщения коммитов на **английском**.
- Проект независимый: не добавляй ассеты, названия или тексты оригинальной игры.

## Запуск

```bash
python3 -m http.server 8000   # затем http://localhost:8000
```

Через `file://` ничего не работает: ES-модули и доступ к микрофону требуют `http://localhost` или `https`.

## Структура

```
index.html, css/style.css
js/
  main.js        — объект nav: переходы между экранами
  ui.js          — h() (мини-hyperscript), mount(), toast(), countdown(), drawWave() и т. п.
  audio.js       — AudioContext, микрофон, Recorder (MediaRecorder), decode, sliceBuffer, seekVideo
  analysis.js    — признаки голоса (YIN-тон, RMS-огибающая) и сравнение через DTW → метрики 0..1
  judges.js      — три судьи: веса метрик, шкала 0..10, реплики-комментарии
  packs.js       — демо-пак (синтез), подготовка реплик, IndexedDB, экспорт/импорт .zip
  stage.js       — «сцена» реплики: волна или видео + суфлёр (субтитр)
  timeline.js    — canvas-таймлайн редактора (волна, реплики, drag/resize, zoom)
  subtitles.js   — парсер .srt/.vtt, запись .srt
  zip.js         — минимальный ZIP (запись stored, чтение stored/deflate)
  screens/       — menu, setup, game, packs, editor, dub
.github/workflows/pages.yml — деплой на GitHub Pages
```

## Соглашения по коду

- Стиль: 2 пробела, одинарные кавычки, точки с запятой, `const`/`let`, стрелочные функции, async/await. Ориентируйся на соседний код: та же плотность комментариев (короткие, объясняют «почему»), те же идиомы.
- DOM строится через `h(tag, props, ...children)` из `ui.js`, без innerHTML со строками и без шаблонизаторов. Обработчики событий передаются как `onclick`, `oninput` и т. п.
- Каждый экран — функция `xxxScreen(nav, ...)`, которая вызывает `mount(el, onLeave)`. В `onLeave` обязательно останавливай всё запущенное: `requestAnimationFrame`, аудиоисточники, `<video>`, рекордеры, слушатели на `document`.
- Новые экраны регистрируются в `nav` в `main.js`.
- Цвета и размеры берутся из CSS-переменных в `:root` (`--accent`, `--card`, `--line` …). Не хардкодь новые цвета в JS: canvas читает их через `getComputedStyle`.
- Ошибки для пользователя показываются через `toast(msg, { error: true })` на русском и с конкретной причиной. Подробности пиши в `console.error/warn`. Не глотай ошибки молча.

## Данные и совместимость

- IndexedDB: база `dub-club`, store `packs`, keyPath `id`. Два вида паков:
  - обычный: `{ id, name, lines: [{ id, title, hint, kind: 'audio'|'video', blob, start, end, duration }] }`;
  - видеопак из редактора: `{ id, name, type: 'video', video: Blob, videoName, cues: [{ id, start, end, text }] }`. Для игры он разворачивается в `lines` функцией `withLines()`.
- Файл пака (`*.dubpack.zip`) содержит `pack.json` (`format: 'dub-club-pack'`, `version: 1`), `subtitles.srt` и видео. У пользователей уже есть сохранённые паки и файлы: **меняй схему только с обратной совместимостью**, а при несовместимых изменениях повышай `version` и поддерживай чтение старых версий.
- В сохраняемых объектах не должно быть несериализуемого (AudioBuffer, DOM-узлы, функции): пропускай всё через `serializable()`.

## Известные подводные камни браузеров

Эти грабли уже собраны, не наступай на них повторно:

- **IndexedDB при нехватке квоты** прерывает транзакцию событием `abort` без `error`. Всегда обрабатывай `tx.onabort`. В инкогнито квота маленькая, видео туда часто не помещается.
- **Blob, привязанный к файлу** (выбранный `File` или срез из zip), некоторые браузеры не могут положить в IndexedDB. Поэтому `saveCustomPack` повторяет попытку, предварительно скопировав байты в память.
- **`decodeAudioData` целого видео** падает на больших файлах (память) и на кодеках, которые `<video>` играет, а декодер не умеет (AC3, часть MKV). Для видеореплик есть запасной путь `captureSegment()`: отрезок проигрывается беззвучно и записывается. Файлы больше `MAX_FULL_DECODE` (200 МБ) целиком не декодируются.
- **`createMediaElementSource`** можно вызвать только один раз на элемент. После этого звук элемента идёт только через граф Web Audio, а `muted` даёт тишину и в графе.
- **WebM из MediaRecorder** часто имеет `video.duration === Infinity`. Бери длительность из декодированного звука.
- Автовоспроизведение со звуком требует предшествующего жеста пользователя. Запускай воспроизведение по клику.

## Анализ голоса и оценки

- `extractFeatures()` ресемплирует звук в 16 кГц моно, кадры по 20 мс, обрезает тишину по краям. Не меняй константы без проверки на демо-паке.
- `compare()` возвращает метрики в диапазоне 0..1 либо `{ silent: true }` / `{ silent: true, refSilent: true }`. Судьи в `judges.js` только взвешивают метрики, и шкала там одна (`toTen`).
- Контрольная проверка после изменений в анализе: реплика против самой себя должна давать ≈10 у всех судей, разные демо-реплики — заметно меньше.

## Проверка изменений

Тестового фреймворка в репозитории нет. Перед коммитом:

1. Запусти сервер и пройди затронутый сценарий в браузере.
2. Для автоматической проверки используй Playwright (в облачной среде он уже установлен вместе с Chromium, браузеры скачивать не нужно) с флагами:
   ```
   --use-fake-ui-for-media-stream --use-fake-device-for-media-stream --autoplay-policy=no-user-gesture-required
   ```
   Фейковый микрофон выдаёт периодический тон, этого хватает для полного раунда. Собирай `console`/`pageerror`: ошибок быть не должно.
3. Тестовое видео можно сгенерировать прямо в странице: canvas + осциллятор → `MediaRecorder` (`video/webm;codecs=vp8,opus`).
4. Временные скрипты и файлы держи вне репозитория.

## Git

- Основная ветка разработки — **`develop`**. Работай в отдельной ветке от `develop` и вливай изменения через PR в `develop`. Без явной просьбы не пушь напрямую в `develop` и `main`.
- Коммиты небольшие и осмысленные, с сообщением на английском: заголовок в повелительном наклонении, в теле объясни «почему».
- Перед пушем обнови README, если изменились возможности, структура или способ запуска.

## Деплой

`.github/workflows/pages.yml` выкладывает `index.html`, `css/` и `js/` на GitHub Pages при пуше в ветки из `on.push.branches`. Новые каталоги с файлами сайта нужно добавить в шаг `Collect site files`. Pages включается в настройках репозитория (Source: GitHub Actions); для приватного репозитория нужен платный план GitHub.
